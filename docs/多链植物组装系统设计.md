# 多链植物组装系统设计

## 核心设计理念

将植物拆分成多个部分，每个部分必须在不同的链上铸造，最终在 ZetaChain 上组装成完整的植物 NFT。**ZetaChain 成为必需品**，因为：
1. **种子必须在 ZetaChain 铸造**（起点）
2. **组装必须在 ZetaChain 完成**（终点）
3. **跨链传输必须通过 ZetaChain**（枢纽）

---

## 植物部分划分

### 5个核心部分

| 部分 | 链 | 对应植物部位 | 视觉特征 | 铸造要求 |
|------|-----|------------|---------|---------|
| **种子 (Seed)** | **ZetaChain** ⭐ | 种子/核心 | DNA 信息、基础配色 | **必需，第一步** |
| **根 (Root)** | **Bitcoin** | 根部系统 | 低频音频驱动的根部 | 需要 BTC 支付 |
| **茎 (Stem)** | **Ethereum** | 主干/茎 | 中频音频驱动的茎干 | 需要 ETH 支付 |
| **枝干 (Branch)** | **Polygon/BSC** | 分支系统 | 中高频音频驱动的分支 | 需要 MATIC/BNB 支付 |
| **叶子 (Leaf)** | **Arbitrum/Optimism** | 叶子/花朵 | 高频音频驱动的叶子 | 需要 ETH/L2 代币支付 |

### 部分与音频频段的映射

```
┌─────────────────────────────────────────────────────────┐
│           植物部分 ↔ 音频频段 ↔ 链的映射关系              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  🎵 低频 (Bass)    → 根 (Root)    → Bitcoin             │
│  🎵 中频 (Mid)     → 茎 (Stem)    → Ethereum            │
│  🎵 中高频 (Mid-High) → 枝干 (Branch) → Polygon/BSC     │
│  🎵 高频 (Treble)  → 叶子 (Leaf)  → Arbitrum/Optimism   │
│                                                         │
│  🌱 种子 (Seed)    → DNA 信息     → ZetaChain ⭐        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 阶段 2-5: 多链铸造植物部分

用户需要依次在不同链上铸造植物的各个部分：

#### 2. 根 (Root) - Bitcoin

```
用户在 ZetaChain 上拥有种子 NFT
    ↓
切换到 Bitcoin 网络（通过 ZetaChain 的 BTC 支持）
    ↓
使用种子 ID 作为参数，在 Bitcoin 上铸造根 NFT
    ↓
根 NFT 包含：
  - 种子 ID 引用
  - 根部的视觉数据（低频音频驱动）
  - 铸造链信息
```

#### 3. 茎 (Stem) - Ethereum

```
用户拥有种子 + 根 NFT
    ↓
切换到 Ethereum 网络
    ↓
使用种子 ID 作为参数，在 Ethereum 上铸造茎 NFT
    ↓
茎 NFT 包含：
  - 种子 ID 引用
  - 茎部的视觉数据（中频音频驱动）
```

#### 4. 枝干 (Branch) - Polygon/BSC

```
用户拥有种子 + 根 + 茎 NFT
    ↓
切换到 Polygon/BSC 网络
    ↓
使用种子 ID 作为参数，铸造枝干 NFT
```

#### 5. 叶子 (Leaf) - Arbitrum/Optimism

```
用户拥有种子 + 根 + 茎 + 枝干 NFT
    ↓
切换到 L2 网络
    ↓
使用种子 ID 作为参数，铸造叶子 NFT
```

### 阶段 6: 跨链传输到 ZetaChain

```
用户收集齐所有部分后：
    ↓
通过 ZetaChain 的跨链功能，将所有部分传输到 ZetaChain
    ↓
每个部分 NFT 在源链上被销毁
    ↓
在 ZetaChain 上重新铸造对应的部分 NFT
```

### 阶段 7: 组装完整植物（ZetaChain）

```
用户在 ZetaChain 上拥有所有部分 NFT
    ↓
调用组装函数 assemblePlant(seedId, rootId, stemId, branchId, leafId)
    ↓
验证：
  - 所有部分都属于同一个种子 ID
  - 所有部分都由同一用户拥有
  - 所有部分都已传输到 ZetaChain
    ↓
销毁所有部分 NFT
    ↓
铸造完整的植物 NFT
    ↓
完整植物 NFT 包含：
  - 所有部分的视觉数据合并
  - 完整的 DNA 信息
  - 组装时间戳
  - 所有参与链的证明
```

## 智能合约设计

### 1. ZetaChain 种子合约（ZetaChainUniversalNFT.sol 扩展）

```solidity
contract PlantSeedNFT is ZetaChainUniversalNFT {
    // 种子 ID 到 DNA 的映射
    mapping(uint256 => bytes) public seedDNA;
    
    // 种子 ID 到创建者的映射
    mapping(uint256 => address) public seedCreator;
    
    // 铸造种子
    function mintSeed(
        string memory metadataURI,
        bytes calldata dnaData
    ) public payable returns (uint256 seedId) {
        seedId = _nextTokenId;
        _nextTokenId++;
        
        _safeMint(msg.sender, seedId);
        _setTokenURI(seedId, metadataURI);
        seedDNA[seedId] = dnaData;
        seedCreator[seedId] = msg.sender;
        
        emit SeedMinted(msg.sender, seedId);
    }
    
    // 获取种子 DNA
    function getSeedDNA(uint256 seedId) public view returns (bytes memory) {
        return seedDNA[seedId];
    }
}
```

### 2. 植物部分合约（各链部署）

```solidity
contract PlantPartNFT is ERC721 {
    // 部分类型枚举
    enum PartType { Root, Stem, Branch, Leaf }
    
    // 部分信息结构
    struct PartInfo {
        uint256 seedId;        // 关联的种子 ID
        PartType partType;      // 部分类型
        string chainName;       // 铸造链名称
        address creator;        // 创建者
        uint256 timestamp;      // 铸造时间
    }
    
    // Token ID 到部分信息的映射
    mapping(uint256 => PartInfo) public partInfo;
    
    // 种子 ID 到已铸造部分的映射
    mapping(uint256 => mapping(PartType => uint256)) public seedParts;
    
    // 铸造植物部分
    function mintPart(
        uint256 seedId,
        PartType partType,
        string memory metadataURI
    ) public payable returns (uint256 tokenId) {
        // 验证：该种子的该部分尚未铸造
        require(
            seedParts[seedId][partType] == 0,
            "Part already minted for this seed"
        );
        
        tokenId = _nextTokenId++;
        _safeMint(msg.sender, tokenId);
        _setTokenURI(tokenId, metadataURI);
        
        partInfo[tokenId] = PartInfo({
            seedId: seedId,
            partType: partType,
            chainName: getChainName(), // 获取当前链名称
            creator: msg.sender,
            timestamp: block.timestamp
        });
        
        seedParts[seedId][partType] = tokenId;
        
        emit PartMinted(msg.sender, tokenId, seedId, partType);
    }
    
    // 获取链名称（需要在各链上实现）
    function getChainName() internal pure virtual returns (string memory);
}
```

### 3. 组装合约（ZetaChain）

```solidity
contract PlantAssembler is Ownable {
    PlantSeedNFT public seedContract;
    PlantPartNFT public partContract; // ZetaChain 上的部分合约
    
    // 组装事件
    event PlantAssembled(
        address indexed assembler,
        uint256 indexed seedId,
        uint256 indexed plantTokenId,
        uint256 rootId,
        uint256 stemId,
        uint256 branchId,
        uint256 leafId
    );
    
    // 组装植物
    function assemblePlant(
        uint256 seedId,
        uint256 rootId,
        uint256 stemId,
        uint256 branchId,
        uint256 leafId
    ) public returns (uint256 plantTokenId) {
        // 验证：所有部分都属于同一个种子
        require(
            partContract.partInfo(rootId).seedId == seedId &&
            partContract.partInfo(stemId).seedId == seedId &&
            partContract.partInfo(branchId).seedId == seedId &&
            partContract.partInfo(leafId).seedId == seedId,
            "Parts must belong to same seed"
        );
        
        // 验证：用户拥有所有部分
        require(
            partContract.ownerOf(rootId) == msg.sender &&
            partContract.ownerOf(stemId) == msg.sender &&
            partContract.ownerOf(branchId) == msg.sender &&
            partContract.ownerOf(leafId) == msg.sender,
            "Must own all parts"
        );
        
        // 验证：种子存在且由用户创建
        require(
            seedContract.ownerOf(seedId) == msg.sender,
            "Must own the seed"
        );
        
        // 销毁所有部分 NFT
        partContract.burn(rootId);
        partContract.burn(stemId);
        partContract.burn(branchId);
        partContract.burn(leafId);
        
        // 销毁种子 NFT
        seedContract.burn(seedId);
        
        // 铸造完整植物 NFT
        plantTokenId = plantContract.mintCompletePlant(
            msg.sender,
            seedId,
            rootId,
            stemId,
            branchId,
            leafId
        );
        
        emit PlantAssembled(
            msg.sender,
            seedId,
            plantTokenId,
            rootId,
            stemId,
            branchId,
            leafId
        );
    }
}
```

## 总结

### 为什么 ZetaChain 成为必需品？

1. **种子必须在 ZetaChain**：这是整个流程的起点
2. **组装必须在 ZetaChain**：这是整个流程的终点
