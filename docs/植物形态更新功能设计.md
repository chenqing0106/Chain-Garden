# 植物形态更新功能设计

## 问题描述

用户问：**生成的植物已经铸造上链了，未来还能通过新的交互来改变它的形态吗？**

## 当前状态

### ❌ 当前不支持

目前合约设计只支持：
- ✅ 铸造NFT（`mint` / `safeMint`）
- ✅ 设置基础URI（仅owner，影响所有token）
- ❌ **不支持单个NFT持有者更新自己的元数据**

一旦植物铸造上链，其元数据URI就被固定，无法通过新的交互来改变形态。

## 解决方案

### 方案1：允许持有者更新元数据URI（推荐）

**核心思路**：允许NFT持有者更新自己NFT的元数据URI，从而支持形态变化。

#### 1.1 合约修改

在 `ZetaChainUniversalNFT.sol` 和 `ChainGardenNFT.sol` 中添加更新功能：

```solidity
// 在合约中添加
mapping(uint256 => uint256) public updateCount; // 记录更新次数
mapping(uint256 => string[]) public updateHistory; // 更新历史记录

event PlantUpdated(
    address indexed owner,
    uint256 indexed tokenId,
    string newMetadataURI,
    uint256 updateCount
);

/**
 * @dev Update plant metadata (only owner can update their own NFT)
 * @param tokenId The token ID to update
 * @param newMetadataURI New metadata URI (must be uploaded to IPFS first)
 */
function updatePlantMetadata(
    uint256 tokenId,
    string memory newMetadataURI
) public {
    require(_ownerOf(tokenId) != address(0), "Token does not exist");
    require(_ownerOf(tokenId) == msg.sender, "Not the owner");
    require(bytes(newMetadataURI).length > 0, "Invalid metadata URI");
    
    // 记录更新历史
    updateHistory[tokenId].push(tokenURI(tokenId));
    
    // 更新元数据
    _setTokenURI(tokenId, newMetadataURI);
    _tokenMetadata[tokenId] = newMetadataURI; // 如果使用 ChainGardenNFT
    
    // 增加更新计数
    updateCount[tokenId]++;
    
    emit PlantUpdated(msg.sender, tokenId, newMetadataURI, updateCount[tokenId]);
}

/**
 * @dev Get update history for a token
 */
function getUpdateHistory(uint256 tokenId) public view returns (string[] memory) {
    return updateHistory[tokenId];
}
```

#### 1.2 前端实现流程

```typescript
// 1. 用户与植物交互（新的音频、文字等）
async function evolvePlant(
  tokenId: string,
  newInteraction: {
    audio?: AudioData;
    text?: string;
    image?: File;
  }
) {
  // 2. 基于现有DNA + 新交互，生成新的植物形态
  const currentMetadata = await fetchNFTMetadata(tokenId);
  const currentDNA = currentMetadata.dna;
  
  // 3. AI分析新交互，生成更新的DNA或直接生成新形态
  let newDNA: PlantDNA;
  if (newInteraction.text) {
    // 基于文字生成新DNA（可以融合旧DNA）
    newDNA = await aiService.generateEvolvedDNA(
      currentDNA,
      newInteraction.text
    );
  } else if (newInteraction.audio) {
    // 基于音频生成新形态
    newDNA = await generateDNAFromAudio(newInteraction.audio);
  }
  
  // 4. 渲染新形态
  const newImage = await renderPlant(newDNA, newInteraction.audio);
  
  // 5. 创建新元数据（包含更新历史）
  const newMetadata = {
    ...currentMetadata,
    name: `${currentMetadata.name} (Evolved)`,
    image: newImage,
    dna: newDNA,
    attributes: [
      ...currentMetadata.attributes,
      {
        trait_type: "Evolution Count",
        value: (currentMetadata.evolutionCount || 0) + 1,
        display_type: "number"
      },
      {
        trait_type: "Last Evolution",
        value: new Date().toISOString()
      }
    ],
    evolutionHistory: [
      ...(currentMetadata.evolutionHistory || []),
      {
        timestamp: Date.now(),
        trigger: newInteraction.text || "audio",
        dna: newDNA
      }
    ]
  };
  
  // 6. 上传新元数据到IPFS
  const newMetadataURI = await ipfsService.upload(newMetadata);
  
  // 7. 调用合约更新
  const contract = await getContract();
  const tx = await contract.updatePlantMetadata(tokenId, newMetadataURI);
  await tx.wait();
  
  return { txHash: tx.hash, newMetadataURI };
}
```

### 方案2：创建进化版本NFT（链式NFT）

**核心思路**：不修改原NFT，而是创建新的"进化版本"NFT，形成进化链。

#### 2.1 合约设计

```solidity
mapping(uint256 => uint256) public evolutionChain; // tokenId -> nextEvolutionId
mapping(uint256 => uint256) public parentTokenId; // evolutionId -> parentId

event PlantEvolved(
    address indexed owner,
    uint256 indexed parentTokenId,
    uint256 indexed evolutionTokenId
);

/**
 * @dev Evolve a plant into a new version
 */
function evolvePlant(
    uint256 parentTokenId,
    string memory evolutionMetadataURI
) public returns (uint256 evolutionTokenId) {
    require(_ownerOf(parentTokenId) == msg.sender, "Not the owner");
    
    // 铸造新版本NFT
    evolutionTokenId = _nextTokenId++;
    _safeMint(msg.sender, evolutionTokenId);
    _setTokenURI(evolutionTokenId, evolutionMetadataURI);
    
    // 建立进化链关系
    evolutionChain[parentTokenId] = evolutionTokenId;
    parentTokenId[evolutionTokenId] = parentTokenId;
    
    emit PlantEvolved(msg.sender, parentTokenId, evolutionTokenId);
}
```

#### 2.2 优势与劣势

**优势**：
- ✅ 保留所有历史版本
- ✅ 可以交易不同版本
- ✅ 不修改原NFT（符合NFT不可变性原则）

**劣势**：
- ❌ 需要多次铸造（gas费用）
- ❌ 管理多个NFT更复杂

## 推荐方案对比

| 特性 | 方案1：更新元数据 | 方案2：进化链NFT |
|------|-----------------|-----------------|
| **Gas费用** | 低（只需更新） | 高（每次铸造新NFT） |
| **历史保留** | 需要手动记录 | 自动保留 |
| **交易性** | 单一NFT | 多版本可交易 |
| **实现复杂度** | 中等 | 较高 |
| **符合NFT原则** | ⚠️ 修改了元数据 | ✅ 完全不可变 |

## 混合方案（最佳实践）

结合两种方案的优点：

1. **允许更新元数据**（方案1）- 用于日常形态变化
2. **记录重要里程碑**（方案2）- 创建"里程碑NFT"记录重要进化节点

```typescript
// 日常更新：直接更新元数据
await contract.updatePlantMetadata(tokenId, newMetadataURI);

// 重要里程碑：创建新NFT
if (isMilestone(evolution)) {
  const milestoneTokenId = await contract.evolvePlant(tokenId, milestoneMetadataURI);
  // 里程碑NFT可以单独交易，但日常更新在原NFT上
}
```

## 总结

**回答用户问题**：

> **是的，可以实现！** 通过添加 `updatePlantMetadata` 功能，用户可以在植物铸造后通过新的交互（文字、音频、图片）来改变其形态。每次更新会：
> 1. 生成新的植物形态（基于旧DNA + 新交互）
> 2. 上传新元数据到IPFS
> 3. 更新NFT的元数据URI
> 4. 保留进化历史记录

这样既保持了NFT的所有权不变，又允许植物"成长"和"进化"，增加了交互性和长期价值。
